# Специфікація продукту: Локальний HTTP-сервіс реєстру задач (ЛР 1)

## 1. Проблема та мета
Замовник хоче перетворювати повідомлення після зустрічей на задачі без втрати інформації. Мета — створити легкий локальний HTTP-сервіс на FastAPI, який підтримує ручне створення задач, перегляд списку та створення задачі з неструктурованого тексту за допомогою мовної моделі з жорстким захистом від галюцинацій (модель лише пропонує, програма перевіряє).

## 2. Обсяг роботи (Scope)
- **Включено:**
  - `GET /tasks` — перегляд списку всіх збережених задач (JSON-масив).
  - `POST /tasks` — ручне створення задачі з повним набором полів.
  - `POST /tasks/from-text` — створення задачі з вільного тексту через LLM із валідацією полів та політики збереження.
  - Синтетичне сховище у вигляді локального JSON-файлу.
- **Виключено (Non-goals):**
  - Автономний PM-агент, tools/MCP, RAG.
  - Хмарна інфраструктура, авторизація, база даних SQL, складний UI (тільки API / Swagger).

## 3. Продуктовий контракт полів задачі
Кожна задача містить 4 обов'язкові поля:
1. `title` (рядок, 3–120 символів) — коротка назва задачі.
2. `description` (рядок або `null`) — опис зустрічі чи деталі.
3. `assignee` (рядок) — відповідальний-псевдонім.
4. `due_date` (рядок у форматі `YYYY-MM-DD`) — строк виконання.
- Технічний `id` (унікальний рядок або число) генерується сервісом автоматично.

## 4. Маршрути та відповіді HTTP
- `GET /tasks`: повертає `200 OK` та масив усіх записів.
- `POST /tasks` (ручне): очікує поля задачі. Успіх повертає `201 Created` та створений об'єкт із `id`. При невалідних полях — `422 Unprocessable Entity`.
- `POST /tasks/from-text`: очікує тіло `{"text": "..."}`.
  - Успіх (модель + валідація пройдені): повертає `201 Created` та новий запис.
  - Неповний або суперечливий текст / збій провайдера / вигадані дані: повертає статус уточнення або відмови (`422` або відповідний код помилки) і **не змінює стан сховища**.

## 5. Критерії приймання (Acceptance Criteria)
- **AC1 (Список):** `GET /tasks` завжди повертає валідний JSON-масив і не залежить від працездатності LLM.
- **AC2 (Ручне створення):** `POST /tasks` додає рівно один запис, збільшує довжину списку на 1, не чіпає попередні записи.
- **AC3 (Хибний ручний вхід):** Неправильні дані дають помилку `422`, кількість записів у базі не змінюється.
- **AC4 (Коректний AI-запит):** Текст із валідними даними та відповідальним перетворюється на задачу, поля підтверджуються вхідним текстом.
- **AC5 (Неповний/суперечливий текст):** Відсутність дати або конфлікт кількох дат у тексті призводить до відмови/уточнення без створення задачі.
- **AC6 (Захист від галюцинацій):** Якщо модель пропонує дату чи ім'я, яких немає у вхідному тексті, програма відхиляє запис.
- **AC7 (Fallback при збої провайдера):** При падінні LLM сервіс повертає помилку, а ручний шлях продовжує працювати.

## 6. Завдання агенту для програмування
- **Мета:** Написати код FastAPI-сервісу (`app/main.py`), логіку сховища та тести (`tests/test_service.py`) згідно з цією специфікацією.
- **Обмеження:** Використовувати лише Python, FastAPI, Pydantic, OpenAI SDK для OpenRouter (`nvidia/nemotron-3-super-120b-a12b:free`). Секрети тримати лише в `.env`. Не змінювати ручний шлях при збоях моделі.
- **Точки зупинки для агента:** Агент зобов'язаний зупинитися і запитати PM, якщо виникає неоднозначність у полях, спроба додати платний маршрут або вихід за межі scope.
